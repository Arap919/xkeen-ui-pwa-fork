## ✨ Особенности

- 🚀 Установка одной командой
- 📉 Низкое потребление ресурсов
- ⛔ Никаких зависимостей кроме XKeen
- ⚓️ Порт по умолчанию: 1000 (меняется в `/opt/etc/init.d/S99xkeen-ui`)
- 🎛️ Управление сервисом: `/opt/etc/init.d/S99xkeen-ui start|restart|stop|status`

&nbsp;

## ⚙️ Функционал

- 📊 Мониторинг и управление сервисом
- 📝 Редактирование конфигураций с валидацией и форматированием
- 📜 Просмотр логов с автообновлением и фильтрацией
- 🕒 Выбор часового пояса в логах
- 🔀 Переключение/установка/обновление ядер Xray и Mihomo
- 🔗 Генерация аутбаундов из ссылок (также доступно [отдельно по ссылке](https://zxc-rv.github.io/XKeen-UI/Outbound_Generator/))
- 🩻 Сканирование dat файлов
- ⚔️ Clash API реализация для Mihomo
- 📡 Применение и бэкап конфигов на выбранные роутеры (Настройки -> Плагины)

## ⚡️ Быстрый старт (установка/обновление/удаление)

### Cтабильная/Latest версия

```SH
curl -fsSL https://raw.githubusercontent.com/Arap919/xkeen-ui-pwa-fork/main/setup.sh | sh
```

Релизы форка публикуются автоматически по тегам `vX.Y.Z+pwa.N`; установщик всегда использует последний стабильный релиз форка.

После слияния PR из `upstream-sync/main` в `main` автоматически создаётся и отправляется релизный тег на коммите слияния. Версия `X.Y.Z` берётся из наибольшего стабильного тега upstream, вошедшего в синхронизированный коммит. Счётчик `pwa.N` увеличивается только внутри этой версии: при переходе на новую upstream-версию он начинается с `pwa.1`. Повторный запуск для уже помеченного коммита не создаёт новый тег.

Для автоматической публикации секрет GitHub Actions `UPSTREAM_PR_TOKEN` должен иметь права **Contents: read/write** и **Pull requests: read/write** для этого репозитория. Тег отправляется с этим токеном, чтобы запустить workflow сборки релиза.

## Обновления router-watchdog и уведомления

Блок **router-watchdog** показывает установленную и последнюю стабильную версию на локальном роутере, ссылку и описание релиза. Кнопка **Проверить** обновляет сведения; **Установить** требует отдельного подтверждения выбранной версии. Установка может занять несколько минут и продолжается при закрытии страницы. После потери связи повторите проверку версии перед новой попыткой.

Нужна установленная версия router-watchdog с командами `--check-update` и `--install-update --expected-version X.Y.Z-N`. Старый пакет или отсутствие команды отображаются как недоступная проверка; панель продолжает работать. Панель вызывает только эти фиксированные операции, не использует секрет Mihomo и не устанавливает обновления автоматически.

**Включить уведомления** подписывает только текущий браузер после разрешения пользователя. Сервер панели проверяет стабильные релизы каждые 6 часов, в том числе при закрытой странице, и отправляет одно уведомление на новую версию каждой активной подписке. Нажатие уведомления открывает блок обновлений в панели. Для отказа используйте **Отключить уведомления** в том же браузере; просроченные подписки удаляются после ответа 404/410 push-сервиса.

Web Push требует HTTPS с доверенным сертификатом и поддержки Push API. На iPhone/iPad панель необходимо установить на главный экран и открыть оттуда. Проверка в панели доступна независимо от разрешения и поддержки уведомлений. Роутеру нужен исходящий доступ к серверу релизов и push-сервису браузера: Google FCM, Mozilla или Apple; отдельный публичный сервер не нужен. Доставка зависит от браузера, сети и его push-сервиса.

VAPID-ключ автоматически создаётся при первом включении; ключ и подписки хранятся только на роутере в `/opt/etc/xkeen/watchdog-push.json` с правами `0600`. Не публикуйте и не удаляйте этот файл: после потери ключа браузеры нужно подписать заново. Web Push входит в обычную сборку и использует `web-push-native` с криптографией RustCrypto без OpenSSL. Дополнительная настройка ключей вручную не требуется.

## 🌐 Доступ извне

Панель разработана для работы в локальной сети. В случае необходимости использовать панель за пределами локальной сети рекомендуется использовать VPN протоколы, такие как SSTP или Wireguard.
Также поддерживается работа с KeenDNS, для этого нужно в веб-конфигураторе создать саб-домен с протоколом HTTP и портом панели. Обязательно используйте авторизацию и другие меры безопасности!
> [!CAUTION]
> Открытие доступа к панели из интернета без должных мер безопасности может привести к взлому роутера или утечке данных.
> За данные последствия автор проекта ответственность не несет.
