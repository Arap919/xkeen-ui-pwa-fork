# Go и Rust: результаты на роутере

13 ноября 2026 года, 22:09–22:23 по Москве.

**Ускорение от перехода на Go не подтверждено.** В проверенных JSON-сценариях
Go медленнее и расходует больше CPU и памяти. На запросах системных метрик
RCI конечная задержка практически одинаковая. Условие «Go быстрее или
сопоставим» для набора проверенных операций не выполнено; перепись не начата.

## Устройство и сборки

- MediaTek MT7621, MIPS 1004Kc: два ядра, четыре аппаратных потока.
- Linux 4.9-ndm-5; MemTotal 254640 КиБ (248,7 МиБ).
- Go 1.26.3: `GOARCH=mipsle`, `GOMIPS=softfloat`, `CGO_ENABLED=0`.
- Rust 1.101.0-nightly (6f5da406b, 2026-10-10), Axum 0.8.9, Tokio 1.54.1.
- Rust release: opt-level 3, LTO, один codegen unit, panic abort; статическая musl-сборка MIPSel.
- Оба сервера статически скомпонованы. Go-бинарник 6,94 МиБ; Rust 1,82 МиБ.
- Частота счётчиков CPU — 100 тиков/с, прочитана из Linux `AT_CLKTCK`.

## Методика

Серверы запускались по очереди в отдельных временных каталогах `/tmp`,
слушали только loopback и работали с одним JSON из 128 узлов.
Генератор нагрузки также выполнялся на роутере: Wi-Fi и SSH-туннель
в измеренные HTTP-задержки не входят. Для каждого сценария — пять
парных раундов с чередованием Go→Rust и Rust→Go, по восемь секунд.
Перед сценарием выполнялось пять прогревочных запросов.

В первом прогоне проверены `/health`, `/json` при одном и четырёх клиентах,
а также `/system` через настоящий RCI с частотой около одного запроса/с.
В Go числа сначала декодировались стандартным способом в `float64`.
Всего 50 замеров, ошибок HTTP — 0.

Затем для Go проверен `json.Decoder.UseNumber()`, сохраняющий JSON-числа
без преобразования в `float64`. После проверки неизменности JSON-ответа
выполнено ещё пять парных раундов двух JSON-сценариев с тем же Rust-бинарником.
Это ещё 20 замеров, ошибок HTTP — 0. Отставание Go сохранилось.
Изменение чисел — единственное изменение серверного кода между прогонами.

В таблицах указаны медианы метрик пяти раундов, а не квантили объединённой
выборки запросов. CPU — сумма времени пользовательского и системного кода
всех потоков процесса, делённая на число успешных запросов; генератор и
сам RCI в эту метрику серверного процесса не входят.

сохранение чисел не устраняет разницу между этими реализациями.

## Что означают результаты

Для этих реализаций Rust оставляет больше запаса по CPU и памяти.
Переход на Go сам по себе не дал ускорения на данном MIPSel-устройстве.
На редких запросах RCI разница между серверами теряется за задержкой RCI,
поэтому перепись бэкенда не показала пользы для скорости этого сценария.

Это сравнение небольших прототипов с динамическим JSON, а не универсальный
рейтинг языков и не готовая миграция панели. Типизированные модели,
другой способ сериализации или изменения алгоритмов могут дать другие
результаты; в этом эксперименте они не проверялись. Angular не тестировался.
TLS, WebSocket, журналы, редактор, API Mihomo и полноценная панель не измерялись.

Генератор конкурирует с сервером за CPU роутера. Абсолютный RPS поэтому
не равен пределу сервера с внешним генератором. Производственные сервисы
оставались запущенными; фоновая нагрузка не фиксировалась. На Go разброс
некоторых сценариев велик. Точные коэффициенты следует считать оценкой
для этих условий, а не постоянной характеристикой MT7621.

RSS — физическая память процесса после сценария; VmHWM накоплен с запуска
сервера. В первом прогоне сценарии одного сервера выполнялись последовательно,
поэтому память поздних сценариев включает эффект ранних нагрузок. Цифры
прототипов не предсказывают точный RSS полной панели после переписи.

## Проверка и воспроизведение

- 70 завершённых замеров, в каждой группе пять раундов, HTTP-ошибок нет.
- Ответы Go/Rust с общей JSON-фикстурой и тестовым RCI проверены локально.
- После каждого прогона: `CLEANUP_OK`, тестовые исполняемые процессы отсутствуют,
  загруженные бинарники и временные каталоги удалены.
- PID рабочей панели до и после обоих прогонов — 3557.
- Рабочие конфигурации, init-скрипты, маршрутизация и выбор proxy-узла не менялись.
